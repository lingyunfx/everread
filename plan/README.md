# 永读 EverRead 开发计划

> 永远都可以读书

状态：首版功能已全部实现并通过验证（后端 24 项测试、端到端 29 项测试，见第 11 节）。更新日期：2026-11-07。

## 1. 产品目标与范围

构建一个使用 Python / FastAPI、前后端分离的在线阅读应用。用户登录后导入书籍，在个人书架管理和阅读，自动续读，并通过标注、笔记、书签找回内容。

已明确的需求：用户系统、常用格式导入、我的书架、阅读进度自动保存、亮色/暗色/黄色主题、选段标注、右侧笔记、多书签，以及搜索和跳转。

已确认的范围与实施默认值：

- 仅供自己和朋友使用，不开放自助注册。建议由管理员创建和停用账号，首版不依赖邀请邮件。
- 书籍默认仅上传者可见；上传者可以设为公开，进入图书馆。实施默认：“公开”仅对已登录成员开放，不向匿名访客开放。
- 书籍公开不公开任何人的笔记、标注、书签或阅读进度；同一账号可在不同设备继续阅读。
- 第一版完成 PDF、EPUB、TXT 三类格式，分阶段实现，先打通 PDF 阅读闭环。
- 桌面端优先，同时兼容手机浏览器；桌面右侧笔记栏在手机上改为抽屉。
- 阅读搜索限定当前书籍，提供“正文 / 我的笔记 / 我的标注”分类；书签提供独立列表和名称筛选，不建设跨书全文检索。
- 主要在电脑端使用，目标部署为自己的 NAS，使用 Docker Compose；手机保持基础可用，不单独开发移动端应用。
- 小规模成员使用，不引入微服务、独立搜索引擎或消息队列。

暂不纳入首版：OCR、匿名访问和开放注册、社区、AI 解读、付费系统、原生 App、离线整本阅读、DRM 解密、跨书正文搜索、MOBI/AZW3/DOCX 自动转换。扫描 PDF 可阅读、保存进度、添加书签和页级笔记；无文字层时不提供文字选择、句子标注或正文搜索。已自带文字层的扫描 PDF 按实际文字层能力处理。

## 2. 技术架构与模板使用方式

参考 [Full Stack FastAPI Template](https://github.com/fastapi/full-stack-fastapi-template)。截至本次查看，其 README 列出的主要技术包括 FastAPI、SQLModel、PostgreSQL、React、TypeScript、Vite、Tailwind CSS、shadcn/ui，以及认证、生成 API 客户端和测试支持。

注意：模板当前说明中，生产前端可以打包后交给 FastAPI 同域托管。本项目按前后端分离要求调整为独立构建、独立服务；通过反向代理让页面和 `/api/v1` 使用同一域名仍不影响代码和部署分离。

| 层次 | 建议方案 | 职责 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 书架、阅读器、笔记面板与交互 |
| UI | Tailwind CSS + shadcn/ui | 复用模板组件，统一三种主题 |
| 后端 | Python + FastAPI | 用户、鉴权、文件导入、阅读数据 API |
| 数据 | PostgreSQL + SQLModel；数据库迁移沿用模板方案 | 用户与阅读数据持久化 |
| 文件 | 服务器私有目录/持久卷 | 原始书籍与解析产物，不直接公开目录 |
| PDF 阅读 | PDF.js | 页面渲染、文本层、页内定位；应用负责保存标注等数据 |
| EPUB 阅读 | epub.js 与 foliate-js 二选一，阶段 0 对比后确定 | 章节、重排和内容定位 |
| TXT 阅读 | 规范化文本 + 前端分段渲染 | 编码处理、段落定位、选区标注 |
| API 契约 | FastAPI OpenAPI + 生成的 TypeScript 客户端 | 约束前后端字段与错误响应 |
| 部署 | Docker Compose + 反向代理 | 前端、后端、数据库、持久化文件 |

浏览器 → 前端服务；浏览器 → `/api/v1` → FastAPI → PostgreSQL / 私有文件目录。

模板使用方式（已确认）：不整体拷贝模板，而是参考其目录结构、认证、配置、数据库迁移、OpenAPI 客户端生成与测试组织，自建精简版；不带入示例业务模块和注册功能。参考或摘录模板代码处保留 MIT 许可证声明，开始实施时记录参考的上游 commit 和依赖锁文件。后端 Python 3.12，由 uv 管理解释器与依赖。

认证（已确认）：沿用模板的邮箱/密码 + JWT Bearer 令牌方案，补齐阅读接口的资源归属检查。前端统一由 API 客户端附加 `Authorization` 请求头；PDF.js 通过 `httpHeaders` 选项、EPUB 阅读库通过其请求钩子或前端 `fetch` 后交给阅读器的方式携带令牌，阶段 0 验证带令牌的 Range 分段加载。不把令牌放进 URL 查询参数。令牌存储于浏览器本地，需同时做好 XSS 防护（EPUB 内容隔离、禁用脚本）并设置合理有效期；退出时清除。由于不依赖 Cookie，HTTP 与 HTTPS 部署都可登录。禁用模板的公开注册页面和后端注册接口，不只隐藏入口。管理员通过命令行脚本创建/停用账号和重置临时密码，网页管理后台放到后续版本；用户首次登录修改密码；邮件找回暂不依赖 SMTP。

## 3. 页面与功能

### 3.1 用户系统与导入

- 登录、退出、修改密码；不开放自助注册。管理员创建/停用朋友账号，重置临时密码；普通用户不得管理账号。管理员初始账号通过部署配置安全初始化，不写入代码。
- 上传入口支持拖拽和文件选择，显示上传、解析、成功或失败状态。
- 验证扩展名、实际文件类型、大小及解析结果，不单靠文件名判断。
- 书名默认取元数据或文件名，允许编辑；作者、封面缺失时显示占位。
- 同一用户重复上传相同文件时提示已有书籍，保留已有阅读数据。
- 损坏文件、密码保护 PDF、DRM EPUB 返回可理解的提示；首版不负责解锁。
- 建议初始单文件上限 100 MB，作为待确认配置；压缩包另限制解压后大小、文件数和解析时间。

导入流程：上传到临时位置 → 校验 → 建立 processing 记录 → 解析元数据及必要内容 → 标记 ready → 加入可阅读书架；失败记录错误并清理无效临时文件。

首版采用受限并发的后台解析，状态落库；重启后将中断任务标为可重试，提供重试入口。CPU 密集解析置于受限子进程，不阻塞 API 事件循环。无需一开始部署 Redis/Celery；当真实解析负载需要多机调度时再调整。

### 3.2 我的书架

- 导入后立即进入书架，未读、在读、已读可筛选；打开书籍后记录最近阅读时间。
- 展示封面、书名、格式、进度、最近阅读时间，支持书名搜索和最近阅读排序。
- 提供“继续阅读”，恢复上次位置。
- 自己上传的书和从图书馆加入的书都可进入个人书架，各自拥有独立状态与阅读进度。
- 移出个人书架仅移除自己的书架条目，保留个人阅读数据，不删除原书，也不影响其他成员。原书删除规则见图书馆章节。
- 已读状态允许手动设置，不能仅凭偶然翻到最后一页自动判定。

### 3.2.1 图书馆与公开范围

- 新增“图书馆”页面，展示已就绪且设为公开的书籍，支持按书名筛选、打开阅读和加入我的书架。书名筛选不等于跨书正文搜索。
- 上传时默认私有；上传者可在书籍管理中切换私有/公开。只有上传者可以修改书籍元数据、可见性和删除原书，普通读者不能操作。
- 成员直接阅读公开书时自动建立其个人书架记录；共用同一书籍文件，每人的进度、笔记、标注、书签独立保存。上传者也不能通过应用查看朋友的个人阅读记录。
- 公开改回私有后，立即从图书馆隐藏并阻止其他成员的新内容请求；其他成员书架显示“暂不可访问”，保留其已有个人笔记和阅读记录，但禁用原文跳转。再次公开同一书籍时恢复原有定位。已加载到浏览器的内容无法远程撤回。
- 上传者彻底删除原书前显示对其他成员的影响。建议将书籍标记为已删除、清理原文件及派生产物，保留最小书籍信息与每个读者的个人记录；记录标为“原书已删除”，不可跳转，用户可自行清除个人记录。删除自己的阅读记录与删除原书是两个操作。
- 公开不是静态文件公开地址：匿名用户不能浏览图书馆、读取文件或通过分享 URL 绕过登录。

### 3.3 阅读器布局与主题

- 顶部：返回书架、书名、当前位置、搜索、主题和阅读设置。
- 左侧可收起：目录、书签、标注列表。
- 中间：阅读正文，支持滚动、定位和格式适用的缩放/字号设置。
- 右侧可收起：当前书籍笔记列表和笔记编辑器。
- 手机端将两侧面板折叠为抽屉，保证正文可读和按钮可触达。
- 亮色、暗色、暖黄色三种主题保存为用户偏好；黄色只表示视觉配色，不作医学效果承诺。
- EPUB/TXT 可以调整正文背景和字色；PDF 默认保留原稿颜色，界面切换主题，并提供可关闭的暖色覆盖/暗色显示选项。PDF 图像与图表可能受变色影响，需原型验证，不承诺与重排文本完全一致。

### 3.4 自动保存与继续阅读

- 翻页或滚动稳定后短延迟保存，连续阅读期间定时保存；切换书籍或页面隐藏时尽力补存，不能只依赖关闭页面事件。
- 显示“已保存 / 保存中 / 未同步”，失败重试；离线时本机暂存待同步位置，退出账号时清理账号私有缓存。
- 以服务端成功保存的位置作为跨设备续读依据；异常关闭最多可能丢失最后一个尚未保存的短间隔。
- 同一本书、同一用户一份当前进度；采用服务端版本号防止迟到请求覆盖新进度。多设备同时阅读发生冲突时提示选择，不把“最大页码”当作最新位置。
- 标注/搜索跳转后的实际阅读位置可以保存；提供返回跳转前位置的操作。

### 3.5 标注与笔记

- 在可选择文字的书中选中一句或一段，创建高亮，可修改颜色、删除或附加笔记。
- 多行选区保存多个区域；跨页 PDF 选区首版拆成同组的页内标注，不保存一个跨页屏幕矩形。
- 右侧支持创建、编辑和删除笔记，自动保存并显示状态；保存失败保留草稿，重试时不重复创建。
- 笔记可关联标注或当前位置，也可为整本书的普通笔记。整书笔记打开后聚焦笔记，不伪造原文位置。
- 点击标注或带位置的笔记，加载对应内容、滚动定位并短暂强调原文。
- 删除标注时默认保留笔记及其位置快照，避免连带丢失文字；原书被删除后，保留个人笔记和位置快照并提示无法跳转；用户自行删除个人记录时再彻底移除。
- 首版笔记使用纯文本，暂不引入复杂富文本编辑器。

### 3.6 书签与检索

- 同一本书支持多个书签，如第 10 页和第 100 页；可命名、备注、编辑、删除。
- 书签列表显示页码或章节位置，点击即跳转，不覆盖已有其他书签。
- 当前书籍提供统一搜索框，分类选项为“正文 / 我的笔记 / 我的标注”；切换分类后在当前书内查询，不搜索其他用户的记录。结果展示摘要、页码/章节与跳转入口。书签通过独立列表、名称筛选和位置排序快速定位。
- 第一版必须完成上述个人记录检索；普通中文关键字使用数据库子串匹配，限定当前用户、当前书籍并分页，无需单独搜索服务。
- “正文”分类：文本 PDF 按页、EPUB 按章节、TXT 按段落渐进扫描；结果携带原文锚点并支持取消。大书的内存和响应速度在原型中验证。
- 扫描 PDF 无文字层时仍可使用页码跳转、书签、页级笔记及其搜索；不能承诺文字选择或正文搜索，需 OCR 才能补齐。

## 4. 格式能力与稳定定位

| 格式 | 进度 / 书签定位 | 文字标注定位 | 首版边界 |
| --- | --- | --- | --- |
| 文本 PDF | 文件页序号 + 页内位置 | 页序号 + PDF 页面坐标四边形 + 引用文本 | 原稿页码标签与文件第 N 页可能不同；界面区分展示 |
| 扫描 PDF | 文件页序号 + 页内位置 | 无文字层时暂不支持句子选区 | 支持阅读、书签、页级笔记；首版不做 OCR |
| EPUB | 章节 + CFI 内容定位 | CFI 范围 + 引用文本及上下文 | 流式内容不承诺固定页码；固定版式需另验证 |
| TXT | 稳定段落 ID + 段内字符偏移 | 起止段落/偏移 + 引用文本 | 统一编码和换行后固定内容版本；不保存屏幕页码 |

每个位置对象包含 schema_version、文件版本和格式类型；不同格式使用对应字段，不创建通用阅读引擎框架。具体约定：

- PDF UI 页码从 1 开始；渲染内部索引转换集中处理。坐标保存为文档坐标，恢复时考虑旋转、缩放和页面尺寸，禁止保存浏览器屏幕像素。
- EPUB/TXT 改变窗口宽度、字号或主题后，以内容锚点恢复，显示章节/百分比，避免“第 9 页”随布局变化而失效。
- TXT 偏移统一定义为 Unicode 码点，前端负责与 DOM UTF-16 偏移转换，并覆盖 emoji 测试。
- 对每份文件保留 hash 和不可变版本，首版不提供原地替换正文；重新上传新版本作为新书处理。
- 无法恢复精确锚点时尝试引用文本和上下文；仍失败则降级到对应页/章节并提示，禁止静默跳错段落。

## 5. 最小数据模型与 API 范围

| 实体 | 核心数据 |
| --- | --- |
| User | 账号、密码哈希、管理员角色、启用状态、首次改密标记、阅读偏好 |
| Book | owner_id、名称、格式、私有存储键、文件 hash、visibility（private/public）、解析状态、错误、删除状态 |
| BookshelfEntry | user_id + book_id 唯一、未读/在读/已读状态、加入/移出状态、最近阅读时间 |
| ReadingProgress | user_id + book_id 唯一、locator、百分比、revision、更新时间 |
| Annotation | owner_id、book_id、locator/范围、引用原文、颜色、分组 ID |
| Note | owner_id、book_id、可选 annotation_id、可选位置快照、正文、revision、更新时间 |
| Bookmark | owner_id、book_id、locator、名称、备注、创建时间 |

Book 表示上传者拥有的文件与共享设置；BookshelfEntry 表示每位成员的个人书架，公开书被多人阅读时无需复制文件。进度、标注、笔记、书签属于阅读者，其 owner_id 不必等于 Book.owner_id。服务端从当前登录身份确定记录归属；创建记录及原文跳转需验证书籍当前可读，读取个人历史记录只允许记录所有者。

API 按 `/api/v1` 分组：

- 用户：登录/退出、当前用户、密码和偏好；管理员创建/停用账号、重置临时密码；不提供公开注册。
- 书籍：上传、本人上传列表、详情、解析状态/重试、受鉴权的文件读取、修改信息/可见性、删除原书。
- 图书馆：已公开且可读书籍列表；个人书架：加入、移出、恢复及阅读状态更新。
- 进度：获取与带版本号更新。
- 标注、笔记、书签：按书籍创建/查询，按 ID 修改/删除。
- 记录检索：按书籍、关键词、记录类型分页返回摘要和 locator。

正文搜索首版由阅读端处理，无需先搭建服务器全文索引；如性能验证不通过，再在数据库内增加按页/章节文本索引。API 精确路径、状态码和分页字段在实施时由 OpenAPI 固化。

## 6. 数据保护、文件处理与部署

- 书籍读取权限：已登录且账号启用，并且是上传者或书籍为公开；文件及 Range 请求每次检查。书籍修改权限仅上传者；阅读记录查询/修改仅记录所有者。测试猜测 ID、私有/公开切换和停用账号后的越权访问。
- 用户上传文件不进入 Git 仓库、不放入公开静态目录；生产配置、密码和实际书籍不写入提交。
- 上传路径使用服务端生成的 ID；EPUB 解包防止路径穿越、压缩炸弹，限制资源消耗。
- EPUB 内容禁用脚本并进行内容清理和隔离；外部资源默认阻止加载，避免书籍内容访问用户会话或触发跟踪。
- 文件下载支持受鉴权的分段读取，保证大 PDF 可渐进加载；前端令牌方案必须同时兼容阅读器请求。
- 登录及上传设置速率和容量限制；解析设置超时与并发上限。密码使用成熟哈希方案，生产 HTTPS。
- 本地开发：Windows 下运行前后端，数据库可用 Docker Compose。上游 Bash 脚本需提供 PowerShell 等价步骤或明确使用 WSL，避免默认用户可执行 Bash。
- NAS 使用 Docker Compose 部署独立前端/反向代理、FastAPI 和 PostgreSQL；仅暴露网页入口，数据库留在内部网络。
- 持久化数据库、书籍与解析产物，NAS 挂载路径通过配置指定；备份覆盖数据库和文件并验证恢复。重建容器不能丢失书籍或进度。删除操作以删除状态和可重试清理避免遗留文件。

## 11. 实现记录与验证（2026-11-07）

### 与计划的差异

- **API 客户端**：手写轻量类型化客户端（`frontend/src/api/`），未使用 OpenAPI 代码生成；类型与后端 `/api/v1/openapi.json` 保持一致。接口数量稳定后可再引入生成工具。
- **UI 组件**：未引入 shadcn/ui，按同样的风格用 Tailwind 手写了少量基础组件。
- **EPUB 阅读库**：选用 epub.js。foliate-js 未发布到 npm，需以子模块方式引入，首版不采用。安全措施是双层的：后端解析时生成清理过脚本、事件属性和外部资源的副本；前端在禁用脚本的 iframe 中渲染。
- **PDF 解析**：后端使用 PyMuPDF（AGPL，已确认可接受）提取元数据、目录、封面并判断文字层。若正式公开发布，需按 AGPL 补充 LICENSE。

## 12. 第二轮调整（2026-11-07）

按使用反馈做了以下调整：

- **配色**：改为墨黑极简。主色 #24262B，米白背景；暗色主题的强调色为浅灰白，暖黄主题为暖调近黑。
- **上传入口**：从页面顶部移到书架工具栏的“上传”按钮，点开为弹窗；也可以把文件直接拖到书架页面，会显示全屏提示。
- **IDM 弹出下载**：阅读器读取书籍文件时，服务端原来返回 `application/pdf` / `application/epub+zip`，会被 IDM 等下载工具的浏览器扩展按类型拦截。现统一返回自定义类型 `application/x-everread-book`，且不带 Content-Disposition。阅读器按二进制读取文件，不依赖该类型。（本机无 IDM，未用 IDM 实测。）
- **翻页式阅读**：PDF 取消连续滚动，三种格式统一为翻页式阅读。
  - 偏好 `page_layout`（double / single）随账号保存，默认双页。
  - 正文区宽度小于 760px 时自动按单页显示。
  - 双页时封面单独，之后 2-3、4-5 两两成对。
  - 点击左右 30% 区域、方向键 / PageUp / PageDown / 空格、滚轮都可翻页；拖选文字或点到高亮时不翻页。
  - PDF：整页适配，底部有页码跳转框和进度滑块；进度记录这一组的左页。
  - TXT：按章节分节（每节最多 400 段），用 CSS 多栏排版分页，双页即两栏；跨节自动衔接上一节末页 / 下一节首页。
  - EPUB：使用 epub.js 的 spread 实现左右两页。
- **验证**：后端 24 项测试通过；端到端 36 项测试通过（新增 7 项：上传弹窗、文件类型、PDF 双页分组与点击/键盘/滚轮翻页、单双页切换与偏好保存、TXT 两栏跨章翻页、EPUB 双页、窄窗口自动单页）。另用浏览器手动确认了真实 PDF 的双页显示，以及 EPUB 真实鼠标拖选后菜单在松开时弹出。
